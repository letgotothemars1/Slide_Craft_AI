# Design System Master File — SlideCraft AI

> **Как пользоваться:** при сборке конкретной страницы сначала загляни в
> `design-system/slidecraft-ai/pages/<page>.md`. Если файл есть — его правила
> перекрывают этот. Если нет — действуй строго по правилам ниже.

**Проект:** SlideCraft AI
**Стек:** React 18 + Vite + TypeScript, Tailwind 3.4, shadcn/ui (Radix), lucide-react
**Эталонная реализация:** `src/pages/LandingPage.tsx`
**Плотность:** просторная (маркетинг) — на служебных экранах допускается плотнее

---

## Откуда взялся этот файл

Каркас сгенерирован скиллом `ui-ux-pro-max` (`--design-system --persist`), после
чего переписан под реальную систему проекта. Сохранено то, что применимо:
структура страницы, набор анти-паттернов, чеклист перед сдачей, приоритеты
доступности. Заменено то, что не подошло:

| Что предлагал скилл | Почему не подошло |
|---|---|
| Палитра `#2563EB` + оранжевый CTA | В проекте уже есть полный набор токенов с `.dark`-темой, на нём построены все страницы. Перекрасить одну — рассинхронизировать остальные. |
| Plus Jakarta Sans и для заголовков, и для текста | У нас Plus Jakarta Sans на заголовки + Inter на текст. Пара рабочая, менять незачем. |
| Классы `.btn-primary`, `.card`, `.input` голым CSS | Интерфейс собран на shadcn/ui. Свои классы дублировали бы компоненты и разъезжались с ними. |
| Переменные в OKLCH + `@theme inline` | Это для Tailwind v4 / shadcn cli 4. У нас Tailwind 3.4 со space-separated HSL — текущая запись правильная, OKLCH сломал бы тему. |
| GSAP + ScrollTrigger для появления блоков | GSAP в проекте нет. Ради fade-in тянуть зависимость не нужно — хватает CSS-переходов. |
| Глассморфизм как ведущий стиль | Применён точечно (шапка с `backdrop-blur`). Остальной интерфейс — плоские карточки с мягкой тенью, и это осознанно. |
| `.card { cursor: pointer }` | Карточки у нас некликабельны. Указатель на неинтерактивном блоке — ложный аффорданс. |

## Цвет

Все цвета — только через семантические токены из `src/index.css`. **Хардкод
`hsl(...)` и `#hex` в компонентах запрещён**: он не переключается вместе с темой
и разъезжается с остальным интерфейсом.

| Роль | Токен | Значение (light) | Применение |
|---|---|---|---|
| Основной | `--primary` | `221 83% 53%` | Кнопки, ссылки, акценты |
| Акцент | `--accent` | `262 83% 58%` | Только в градиенте с primary |
| Фон страницы | `--background` | `220 20% 97%` | Подложка |
| Фон карточки | `--card` | `0 0% 100%` | Карточки, шапка, футер |
| Текст | `--foreground` | `222 47% 11%` | Заголовки, основной текст |
| Второстепенный текст | `--muted-foreground` | `220 9% 46%` | Описания, подписи |
| Граница | `--border` | `220 13% 91%` | Рамки, разделители |
| Фокус | `--ring` | `221 83% 53%` | Кольцо фокуса |
| Успех (заливка) | `--success` | `142 71% 45%` | Фон бейджа, индикаторы |
| Успех (текст) | `--success-strong` | `142 71% 29%` | **Текст и иконки статуса** |
| Предупреждение (заливка) | `--warning` | `38 92% 50%` | Фон |
| Предупреждение (текст) | `--warning-strong` | `38 92% 32%` | Текст |
| Ошибка | `--destructive` | `0 84% 60%` | Ошибки |

### Заливка и текст — разные токены

Светлые статусные цвета не держат текст. Измеренные контрасты на белой карточке:

```
--success   142 71% 45%  →  2.30:1   ✗ не проходит
--success-strong 142 71% 29%  →  5.11:1   ✓
```

**Правило:** `bg-success` — для заливок, `text-success-strong` — для текста и
иконок. `text-success` использовать нельзя. То же для `warning`.

### Измеренные контрасты (норма 4.5:1)

| Пара | Контраст |
|---|---|
| `foreground` / `background` | 16.67 ✓ |
| `muted-foreground` / `card` | 4.85 ✓ |
| `muted-foreground` / `background` | 4.52 ⚠ проходит впритык |
| `primary-foreground` / `primary` (CTA) | 5.20 ✓ |
| `primary` / `background` (ссылки) | 4.84 ✓ |

⚠ `muted-foreground` на `background` — 4.52 при норме 4.5. Запас почти нулевой,
поэтому **нельзя** дополнительно приглушать его прозрачностью:
`text-muted-foreground/60` уводит пару ниже нормы.

### Акцент и подложки карточек

Ведущий цвет один — `primary`. `accent` работает в паре с ним и самостоятельным
цветом не считается:

- Градиент `gradient-hero` (primary → accent) — на мелких декоративных
  элементах: номера шагов, иконка в CTA-блоке, выделенная часть заголовка.
  Заливать им крупные плоскости не нужно.
- **Подложки карточек:** ключевые карточки получают тонированную панель —
  `bg-primary/[0.04]` или `bg-accent/[0.04]` с рамкой того же цвета на `/20`.
  Чередование двух оттенков даёт сетке ритм, при этом оба цвета остаются
  брендовыми. Третьего оттенка не вводим.
- Обычные карточки остаются на `bg-card`.

## Типографика

- **Заголовки:** Plus Jakarta Sans (`font-display`)
- **Текст:** Inter (`font-body`, по умолчанию)

| Уровень | Классы | Где |
|---|---|---|
| H1 | `font-display text-4xl sm:text-5xl font-extrabold leading-[1.08] tracking-tight` | Только в герое |
| H2 | `font-display text-2xl sm:text-3xl font-bold` | Заголовки секций |
| H3 | `text-sm font-semibold` | Заголовки карточек |
| Лид | `text-base lg:text-lg text-muted-foreground leading-relaxed` | Подзаголовок героя |
| Текст | `text-sm text-muted-foreground` | Основной |
| Описание в карточке | `text-xs leading-relaxed text-muted-foreground` | Внутри карточек |
| Подпись | `text-xs text-muted-foreground` | Мелкие пояснения |

**Минимум для читаемого текста — 12px (`text-xs`).** Меньше допускается только
внутри декоративных макетов (превью слайда в герое), и такой блок обязан нести
`aria-hidden="true"`.

## Отступы и ритм

Секции не должны идти с одинаковым шагом — страница слипается в одну простыню.

| Тип секции | Отступ |
|---|---|
| Герой | `pt-14 sm:pt-20 pb-16` |
| Основная секция | `py-20` |
| Второстепенная / на подложке | `py-16` |
| Внутри карточки | `p-5` |
| Крупный блок (CTA) | `p-10` |

Чередование фона задаёт ритм: секции на `bg-muted/30` c `border-y
border-border/60` разделяют блоки на `bg-background`.

Сетки: `gap-4` между карточками, `gap-10 lg:gap-14` между колонками героя.

## Компоненты

Берём shadcn/ui, свои обёртки не плодим.

### Кнопки

```tsx
<Button size="lg" className="h-12 px-7 text-sm shadow-elevated">   {/* главный CTA */}
<Button size="lg" variant="outline" className="h-12 px-5 text-sm"> {/* вторичный */}
<Button size="sm" className="h-11 sm:h-9">                          {/* в шапке */}
```

`cursor-pointer` уже зашит в базовые классы `button.tsx` — браузер сам по себе
даёт `<button>` курсор `default`, а Tailwind preflight это не исправляет.

**На телефоне любой тач-таргет — минимум 44×44px.** В шапке это `h-11 sm:h-9`:
44px на узких экранах, компактнее от `sm`.

### Карточки

```tsx
{/* обычная */}
<article className="rounded-xl border border-border bg-card p-5 shadow-card
                    transition-shadow hover:shadow-elevated">

{/* акцентная */}
<article className="rounded-xl border border-primary/25 bg-primary/[0.02] p-5 shadow-elevated">
```

Карточки некликабельны: ни `cursor-pointer`, ни `hover:-translate-y`. Движение
по вертикали на ховере дёргает соседей.

### Ссылки текстом

Своё кольцо фокуса обязательно — у `<a>` его нет:

```tsx
className="rounded text-muted-foreground transition-colors hover:text-foreground
           focus-visible:outline-none focus-visible:ring-2 focus-visible:ring-ring
           focus-visible:ring-offset-2"
```

### Иконки

Только lucide-react, 16–20px. Эмодзи вместо иконок — запрещено. Декоративные
иконки получают `aria-hidden="true"`; иконка без текстовой подписи — `aria-label`.

## Структура страницы

Паттерн **Hero → Value → Features → CTA → Footer** (из скилла, подтверждён):

1. Герой с заголовком и визуалом продукта
2. Ценность / как это работает
3. Ключевые возможности — 3–6 карточек
4. Сценарии использования
5. Финальный CTA
6. Футер

CTA дублируется: в шапке (липкая), в герое, в конце. Все три шлют
`track("cta_click", { source })` с разными `source` — воронка на дашборде
считается по ним, менять названия нельзя.

## Движение

Библиотек анимации нет и не нужно. Ни GSAP, ни framer-motion: всё, что делаем,
покрывается CSS-переходами и `IntersectionObserver`, а бандл уже весит
534 КБ и получает предупреждение сборщика.

### Появление при скролле

Компонент `Reveal` (`src/components/Reveal.tsx`) навешивает класс, когда блок
входит в зону видимости; сама анимация живёт в CSS (`.reveal` / `.is-revealed`
в `index.css`).

```tsx
<Reveal>…</Reveal>                        {/* обычный блок */}
<Reveal as="article" delay={i * 80}>…</Reveal>  {/* карточка в сетке, с каскадом */}
```

- Анимируем **только `opacity` и `transform`** — они идут мимо раскладки и
  считаются композитором. `height`, `width`, `top` не трогаем никогда.
- Сдвиг маленький: 14px. Это должно читаться как проявление, а не как отъезд.
- Длительность 500ms, кривая `cubic-bezier(0.22, 1, 0.36, 1)`.
- Каскад в сетке — 80–110ms на элемент. Больше — и последняя карточка приезжает,
  когда читатель уже отвёл взгляд.
- `IntersectionObserver` отключается после первого срабатывания. Повторное
  проигрывание при каждой смене направления скролла делает страницу дёрганой.

### Ховеры

`transition-colors` или `transition-shadow`, 150–300ms. `scale` и `translate`
на ховере запрещены — сдвигают соседей.

### Уважение к настройке системы

Блок `@media (prefers-reduced-motion: reduce)` в `index.css` гасит **всё**:
появление, рост столбиков, мигание каретки. Конечное состояние отрисовывается
сразу. Любая новая анимация обязана попадать в этот блок — контент никогда не
прячется за движением.

## Шапка — одна на всё приложение

`AppHeader` (`src/components/AppHeader.tsx`). **Свою шапку страница не рисует
никогда.** Именно так интерфейс и разъехался: было восемь копий с двумя разными
высотами, тремя наборами ссылок и переключателем языка ровно на одной.

```tsx
<AppHeader />                              {/* обычная страница */}
<AppHeader minimal />                      {/* страница входа */}
<AppHeader onCtaClick={handleCtaClick} />  {/* главная, с трекингом воронки */}
```

Высота `h-14`, липкая, `bg-card/70` с `backdrop-blur-md`. Состав зависит от
авторизации: гостю — вход и регистрация, вошедшему — история, создать, выйти.

## Даты и относительное время

Никакого ручного форматирования и захардкоженной локали.

```tsx
formatDateTime(iso, language)              // 22 сент. 2026 г., 14:05
formatRelativeSeconds(seconds, language)   // 5 сек. назад / 5 sec ago
```

`ru-RU` было зашито в четырёх местах — при английском интерфейсе оставался
русский порядок слов. `Intl.RelativeTimeFormat` вдобавок сам разбирается с
формами множественного числа, чего строки вида `${n} сек назад` не умеют.

## Локализация

Интерфейс двуязычный: русский и английский. Своей i18n-библиотеки нет и не
нужно — словарь лежит в `src/lib/i18n.ts`, язык раздаётся через
`useLanguage()` из `src/context/LanguageContext.tsx`.

```tsx
const { t } = useLanguage();
<h2>{t("steps.title")}</h2>
```

Правила:

- **Ни одной строки текста прямо в разметке.** Всё через `t()` с ключом из
  словаря. Исключение — имя продукта «SlideCraft AI» и доменное имя.
- Словарь типизирован через `satisfies`: ключ без английского перевода **не
  соберётся**. Это намеренно — забытый перевод должен падать на `tsc`, а не
  всплывать пустотой у пользователя.
- Ключи именуются по месту: `features.charts.title`, `nav.login`.
- Выбор языка хранится в `localStorage` и при первом заходе берётся из
  `navigator.language`. Обращение к хранилищу обёрнуто в `try/catch` — в
  приватном режиме оно бросает исключение.
- `document.documentElement.lang` переключается вместе с языком: скринридер
  выбирает голос по нему.
- Переключатель `LanguageToggle` ставится в шапку первым элементом группы
  справа.

**Не путать с языком генерации.** Поле `language` в форме генерации — это язык
*будущей презентации*, он отправляется на бэкенд и к языку интерфейса
отношения не имеет. Связывать их не нужно: человеку может быть удобен русский
интерфейс и английская презентация.

## Анти-паттерны

- ❌ **Хардкод цвета** мимо токенов
- ❌ **`text-success` / `text-warning`** — только `-strong`
- ❌ **Эмодзи вместо иконок**
- ❌ **Тач-таргет меньше 44px** на телефоне
- ❌ **Невидимый фокус** — снимать кольцо нельзя
- ❌ **Мгновенная смена состояния** без перехода
- ❌ **Сдвигающие ховеры** (`scale`, `translate-y`)
- ❌ **Текст мельче 12px** вне декоративных блоков с `aria-hidden`
- ❌ **Тёмная тема по умолчанию**
- ❌ **Ссылки-пустышки** — элемент, похожий на ссылку, обязан вести на живую
  страницу. Не на что вести — не показываем.
